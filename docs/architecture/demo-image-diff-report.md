> 5 个 demo PNG 在构建后出现差异。本文记录回退、根因定位与处理方案。

**状态**：已回退至 `HEAD~1` 版本
**分支**：`dev/document-engine`

## 二、根因链条（实测）

### 生成路径

```
assets/diagrams/*.html
  ↓ build_diagram_artifact
assets/diagrams/generated/png/*-demo.png     （1920×1280 等）
  ↓ _sync_diagram_showcase  （缩放 + 加框）
assets/demos/demo-*.png                       （1241×1754）
```

**关键**：`assets/demos/` 是 `assets/diagrams/generated/` 的**再加工产物**，不是独立制作。

### 受控实验

| 实验 | 结果 |
|---|---|
| 同环境重建 demo（单目标） | **0 像素差异** —— 可复现 |
| `HEAD~1` 版本 vs 当前环境重建 | **5024 像素差异** |

**结论**：差异**不是随机的**，而是**确定性的环境差异** —— 同一环境总能得到相同结果，但**不同环境得到不同结果**。

### 差异性质分析

| 指标 | 值 |
|---|---|
| 差异像素 | 5,024（0.231%） |
| **无明显差异（1–30）** | **4,383** |
| 轻微（31–100） | 622 |
| 较强（101–200） | 19 |
| **严重（>200）** | **0** |
| 有差异的行数 | 114 / 1754 |
| 每行差异中位数 | 35 px |

**形态**：差异集中在**文字区域**，每行少量像素，**无结构性改变**。

**视觉上两图看起来完全相同** —— 我已逐图目视确认。

### 字体来源

```css
font-family: Charter, Georgia, serif
```

**`Charter` 与 `Georgia` 是系统字体**，不在仓库中。仓库内的字体是：

| 文件 | 大小 |
|---|---|
| `LXGWWenKai-Regular.ttf` | 25 MB |
| `LXGWWenKai-Medium.ttf` | 25 MB |
| `SourceSerif4Variable-Roman.ttf` | 1.2 MB |

**根因**：

> demo 图依赖**系统字体**，系统字体版本变化会改变字形抗锯齿，从而改变像素。

---

## 三、为什么这是问题

| 问题 | 后果 |
|---|---|
| **依赖系统字体** | 同一次构建在不同机器产生不同产物 |
| **demo 是构建产物却被追踪** | 每次构建都可能产生 git 差异 |
| **差异无法用产物本身解释** | 只能靠再次构建来验证 |
| **`build.py` 会顺带重建 demo** | 运行无关目标也会改动 `assets/demos/` |

**最后一条是本轮的直接原因**：我跑全量 `build.py`，它重建了图表示例，顺带覆盖了 demo 图。

---

## 三之补：A 阶段的实际范围（本轮新发现）

原以为问题只在 demo 图。实测发现**依赖范围更大**：

```bash
grep -rln "Charter, Georgia" assets/ scripts/ --include="*.html" --include="*.py"
# 33 个文件
```

| 位置 | 数量 |
|---|---|
| `assets/diagrams/*.html` | **图表模板**（23 种图表） |
| `scripts/build.py` | demo HTML 生成（第 579 行） |

**图表模板的字体声明**：

```css
--serif: Charter, Georgia, Palatino, serif;
```

**所以 A 阶段的作用范围是「整个图表体系」而非仅 demo 图**：

```
assets/diagrams/*.html  （33 处 Charter 依赖）
  ↓ 渲染
assets/diagrams/generated/png/*.png   ← 图表产物（有摘要门禁）
  ↓ 再加工
assets/demos/demo-*.png                ← README 图片
```

**这解释了为什么 `assets.py check` 也会失败** —— 图表产物同样依赖系统字体。

### 字体调研结果

仓库内唯一可用的衬线字体：**`Source Serif 4`**（1.1 MB，可变字体，轴 `wght` + `opsz`）。

实测行宽（同一段 11pt 文字）：

| 字体 | 行宽 | 相对 Charter |
|---|---|---|
| Charter（当前） | 472.2pt | 100% |
| **Source Serif 4** | 438.5pt | **92.9%** |
| Georgia | 477.3pt | 101.1% |

**`Source Serif 4` 窄 7%** —— 可通过字号补偿（+8%）接近 Charter。

对比页：`docs/acceptance/font-choice.html`

### A 阶段的决策点

| 选项 | 行宽 | 说明 |
|---|---|---|
| **A1. Source Serif 4 原尺寸** | 92.9% | 与仓库其他文档一致，但字更小 |
| **A2. Source Serif 4 +8%** | ~100% | 行宽接近，字号变大 |
| **A3. 引入新字体** | — | 需调研授权与体积 |
| **A4. 保留 Charter** | 100% | 继续不可复现 |

## 四、方案

### 方案 A：给 demo 图加字体依赖（推荐）

| 步骤 | 内容 |
|---|---|
| A1 | demo 图的 HTML 改用**仓库内字体**（`Source Serif 4` 替代 Charter） |
| A2 | 重建全部 demo 图并提交 |
| A3 | 在 `AGENTS.md` 记录生成命令 |

| 收益 | 代价 |
|---|---|
| 跨环境可复现 | 视觉上字体变化（需评审） |
| 差异可解释 | 一次性的全量重建 |

**风险**：中 —— 视觉会变，但**只变一次**，之后稳定。

### 方案 B：demo 图不进版本控制

| 步骤 | 内容 |
|---|---|
| B1 | `assets/demos/` 加入 `.gitignore` |
| B2 | README 引用改为运行时生成，或保留但标注"构建产物" |
| B3 | CI 在需要时生成 |

| 收益 | 代价 |
|---|---|
| 无 git 噪声 | **README 图片链接失效**（GitHub 不渲染未追踪文件） |
| — | 需改 README |

**风险**：高 —— demo 是 README 的门面，移除追踪会破坏展示。

### 方案 C：分离构建（最小改动）

| 步骤 | 内容 |
|---|---|
| C1 | `build.py` 的 demo 同步改为**显式目标**（`artifact-*` 才做） |
| C2 | 全量 `build.py` **不重建 demo** |
| C3 | 记录 demo 的生成命令 |

| 收益 | 代价 |
|---|---|
| 无关构建不再改动 demo | 差异仍在（只是不被触发） |
| 改动最小 | 未解决根本的可复现性 |

**风险**：低 —— 但**治标不治本**。

### 方案 D：接受差异并记录

| 步骤 | 内容 |
|---|---|
| D1 | 保留当前版本 |
| D2 | 在 `AGENTS.md` 说明 demo 是构建产物、可能随构建更新 |

**风险**：低 —— 但**每次构建都会有无法解释的 diff**。

---

## 五、推荐：A + C 组合

| 阶段 | 内容 | 理由 |
|---|---|---|
| **先做 C** | 全量构建不再重建 demo | **立即止血**：无关改动不再污染 |
| **再做 A** | demo 改用仓库内字体 | **根治**：跨环境可复现 |

**为什么先 C**：

C 是**一行条件判断**，能立刻阻止这个问题再次发生。A 涉及重建全部 demo 并需要视觉评审，应单独进行。

**为什么不选 B**：demo 是 README 的展示内容，必须被追踪。

**为什么不选 D**：接受"每次构建都有无法解释的 diff"违背本轮确立的规范 —— **差异必须可解释**。

| 步骤 | 内容 | 验证 |

### 阶段 A：字体自持（后续）

| 步骤 | 内容 | 验证 |
|---|---|---|
| A1 | 查清图表模板的字体声明 | 文档化 |
| A2 | 改用 `Source Serif 4` | 字体 manifest 校验通过 |
| A3 | 重建全部 demo | 差异评审 |
| A4 | 记录生成命令 | `AGENTS.md` |

## 七、验证设计

| 层 | 方法 | 阈值 |
|---|---|---|
| **L1 构建隔离** | 全量构建后 `git status assets/demos/` | **空** |
| **L2 可复现** | 两次构建的 demo | **0 像素差异** |
| **L3 字体受控** | demo PDF 的字体 | 全部在 manifest 中 |
| **L4 视觉** | 重建后与基线 | 需评审 |

## 八、明确的「不做」

| 不做 | 理由 |
|---|---|
| 移除 demo 追踪 | README 会失效 |
| 接受无法解释的差异 | 违背「差异必须可解释」 |
| 用系统字体继续 | 这是根因 |
