# ADR 0007: Sankey Is Not a V4.3 Grammar

Status: Accepted

Folio V4.3 does not add Sankey. The proposed type does not yet clear the product bar for a distinct, frequent document communication job: bounded contribution comparison is already covered by Bar and Waterfall, while system flow is covered by Architecture, Flowchart, Swimlane, and Sequence.

A production Sankey would also require conservation validation at every internal node, stable multi-edge identity, crossing minimization, band-width legibility, and label placement that remains readable in A4, Letter, responsive HTML, and 16:9 hosts. Those constraints cannot be satisfied by the current shared box-and-route primitives without adding a separate band-layout subsystem and a materially larger validation surface.

Reconsider Sankey only when maintained user fixtures demonstrate a recurring magnitude-flow job that existing grammars misrepresent, and when a bounded prototype passes all four host contracts with deterministic layout, exact accessible data, no hidden aggregation, and no new pixel-level authoring fields. Until then, requests should use Bar or Waterfall for quantities and Architecture, Swimlane, or Sequence for topology and interaction.
