01Release gates

A release stops at a gate when any visual check fails. The build reaches a release candidate in 3.5 days after a short warmup schedule.

  • 12visual gates
  • 3.5 daysbuild time
  • 0blocking checks

A gate is useful only when its failure has a name.

02Build stages

A build job moves from queued to rendered to signed. The warmup schedule is short, the base run is longer, and the large run is the longest.

  • warmupshort schedule
  • baseregular build
  • largelong build

Each stage has a different cost and a different failure mode.

03Sign-off

Sign-off crosses three lanes before the report ships. The analyst writes, the controller checks, and the legal reviewer records the result.

The last lane is a decision, not another edit.

04Gate record

Every gate writes one row: what it checked, who owns the check, and the build in which it last cleared. A row without an owner is an open gate, and an open gate blocks the release.

What the record is for

  • The release job reads the record; a person does not type it twice.
  • A gate that never cleared has no build number, and the release job stops there.
  • An owner is a team, never a single reviewer who may be away.

A record the job cannot read is a note, not a gate.
